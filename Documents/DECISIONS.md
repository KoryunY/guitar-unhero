# Decisions (M0–M1)

Routine, reversible implementation choices made during the M1 run. Spec references are to `GUITAR-UNHERO-MASTER-SPEC.md`.

| ID | Decision | Why / alternatives |
|---|---|---|
| D-01 | One Vite + React 19 + TypeScript app at the repo root; spec "packages" are directories under `src/` (`domain`, `transport`, `audio`, `assessment`, `learning`, `storage`). | §9.1 allows directories before M1 works; avoids workspace overhead. Split into pnpm packages later if needed. |
| D-02 | Pinned: react 19.3.1, vite 8.3.5, @vitejs/plugin-react 6.2.1, typescript 6.0.3, vitest 5.1.0, @playwright/test 1.63.0 (matches the preinstalled Chromium), ajv 8.20.0, ajv-formats 3.0.1. | TypeScript 7 (native port) skipped for tooling compatibility. Lockfile committed. |
| D-03 | No state library; React context + plain classes (`Transport`, `PracticeController`, `AudioEngine`). | §9.1: avoid a framework before a simple model proves insufficient. |
| D-04 | Pitch: original FFT-based YIN, 4096-sample buffer, 512-sample hop, 60–1500 Hz, threshold 0.12, parabolic interpolation on the raw difference function. Runs in a Web Worker. | §AUD-03. Synthetic error ≪1 cent; ~1.5–1.8 ms per frame in Node. No third-party DSP licence questions. |
| D-05 | Onsets: energy rise ≥7 dB over a 50 ms minimum on 64-sample sub-blocks, above an adaptive gate (noise floor +12 dB, ≥−58 dBFS), 90 ms refractory. Attack pitch = median of frames whose whole buffer lies after the onset (≈140 ms evidence). | Simple, deterministic, testable; held notes give one attack. Re-evaluate on real recordings (GU-101). |
| D-06 | Capture: AudioWorklet posts 512-frame chunks stamped with `currentFrame` straight to the worker over a `MessageChannel`; worklet output goes to a zero-gain node (keep-alive, never audible). | §AUD-02/04/05; no SharedArrayBuffer dependency. |
| D-07 | Ajv compiles schemas at runtime, so the production CSP includes `'unsafe-eval'`. | Simplest correct validator with formats enabled. Follow-up: precompile with Ajv standalone and drop `unsafe-eval`. |
| D-08 | Count-in = 4 beats at the current rate; rate/mode/loop changes pause and restart with a count-in; seek starts a new attempt. | §6.3 "pause/restart the segment". |
| D-09 | Matching windows: search ±400 ms bounded by half the neighbour gap; tolerances ±50 cents, ±150 ms calibrated / ±250 ms uncalibrated (labeled approximate); octave-only differences are `uncertain`. Policy id `beginner-1`. | §6.5 beginner tolerances; wider uncalibrated window per §6.2. |
| D-10 | A target with no attack is `incorrect` (reason `no_attack_detected`) only when ≥50 % of its window had usable listening; otherwise `not_assessed`/`uncertain`. Attacks without any pitch evidence are ignored. | §6.5 rule 6; prevents clicks/knocks from being graded. |
| D-11 | Wait mode records the **first** assessed attempt per target (with `recovered_after_retry`) and accepts an attack up to 300 ms before waiting began; rhythm is `not_assessed`. | Honest first-try accuracy without forcing a replay for a slightly early note. |
| D-12 | Leakage: while assessing, synthesized guide notes play only when the output route is "headphones"; on speakers/unknown they're muted with a visible notice. Demonstrations/reference tones block assessment for their duration +350 ms. Metronome uses aperiodic noise clicks. | §5.4. A leakage regression test proves the guide would otherwise be "heard". |
| D-13 | Calibration: one combined `deltaIO`. Loopback = 8 speaker clicks, median lag, accepted if ≥6 heard and IQR ≤20 ms; manual slider labeled "personal adjustment". Valid only for the same device/sample rate/route (manual: same route). | §6.2 single convention, no double subtraction. |
| D-14 | Tuner: 150 ms median history, lock after ≥300 ms stable (spread ≤12 cents) within ±5 cents, unlock beyond ±8; harmonic (≈+12/+19/+24 semitones) and >300-cent cases never give a direction. | §5.2. |
| D-15 | Noise floor falls fast, rises ≈3 dB/s and never while a clearly periodic note sounds. | A sustained string must not be absorbed into the "noise". |
| D-16 | Storage: IndexedDB `guitar-unhero` v1 with stores `settings`, `lessons`, `summaries`. Evidence per step: `sensor`, `self_reported`, `simulated`; strongest wins but a self-report never upgrades to sensor; a lesson is `sensor` only if every attempt step was heard. Export strips device IDs; import is schema+semantic validated, flags records `imported`, and replaces local data after confirmation. | §10.2, AC-06, AC-20. |
| D-17 | Simulation mode generates labeled `simulated:true` attacks (deterministic "accurate/mixed/silent" profiles or buttons). Practice ignores attacks whose `simulated` flag doesn't match the selected input. | AC-06. |
| D-18 | Lesson-1 step "Stop the ringing" reports "I heard the sound stop" when a heard note drops below the gate for 250 ms — it never claims *how* it was stopped. | §5.3 no technique measurement. |
| D-19 | Practice lane view: string 1 on top, time right→left toward a hit line at 16 %; left-handed mirrors direction (left→right) and label side only. Reduced motion advances in whole beats. | §4.3. |
| D-20 | `Documents/` is the documentation directory (the spec's `docs/`). The supplied fixture is imported from `Documents/` directly so it cannot drift. | Start-prompt instruction. |
| D-21 | Extra original drills (`high-e-open`, `high-e-frets`, `b-string-frets`) were authored so lessons don't jump straight to the two-string fixture. | Fixture notes say to use it after single-string lessons. |

## Limitation pass + M2

| ID | Decision | Why / alternatives |
|---|---|---|
| D-22 | JSON Schema validators are precompiled to `src/generated/validators.js` by `scripts/gen-validators.mjs` (Ajv standalone, formats on); a unit test fails if the file is stale. The progress-export schema moved to `src/storage/progress-export.schema.json`. | Removes CSP `'unsafe-eval'` (replaces D-07). |
| D-23 | Screens are lazy-loaded; validators load only with Practice/Data. | Entry bundle 505 kB → ~260 kB. |
| D-24 | Offline: a build plugin emits `sw.js` listing every built file; install precaches all of them; navigations are network-first with cached fallback; assets cache-first (`ignoreVary`). Production only. Data screen shows status and an update control. | GU-104, PRIV-05. No third-party SW library. |
| D-25 | Onsets: energy on a ~21 ms window (was 1.3 ms blocks) **or** spectral flux on log magnitudes (1024-pt, 256 hop, lag 512, threshold max(4 dB/bin, 3×median)). Flux onsets need the newest audio to be loud, a level drop ≤ 6 dB, ≥150 ms since the last onset, and are discarded if they repeat the previous pitch without a ≥3 dB rise. | The guitar-like robustness suite showed multiple false onsets per low note and missed notes under ringing strings. The re-articulation rule protects AC-14 in wait mode. |
| D-26 | Pitch frames whose fundamental is < −40 dB below the strongest partial or < 10 dB above the median spectral floor are not trusted (`missing_fundamental_possibly_several_notes`). Lowest accepted pitch is 78 Hz (standard tuning starts at 82.4 Hz). | Two strings ringing together have a common period nobody played (e.g. E4+B3 → "E2"); this would have produced confident wrong-note judgments. |
| D-27 | Ringing-note cancellation: for an attack after other recent pitches, a cascade of feed-forward comb filters y[n]=x[n]−x[n−T] (fractional T) removes up to two still-ringing pitches before YIN; used only when the raw estimate is unusable; if the raw pitch equals a ringing note while the separated one differs, the attack is `ambiguous_with_ringing_note` (poor). | Recovers the new note when strings ring on (coverage 19 % → 94 % on the synthetic melody) without risking false "wrong note" claims. |
| D-28 | A target whose window contains only an unpitched sound is `uncertain` (`unpitched_sound`), not a miss and not credited. Unpitched onsets within 300 ms after one of the app's metronome clicks are dropped. | Honest when something was heard but its pitch could not be established. |
| D-29 | Diagnostics: explicit, bounded (≤20 s) local recording in the worker; analyzed in-page with the same analyzer (`src/audio/diagnostics.ts`); WAV/label download only on request. `pnpm test:recordings` evaluates saved pairs (AC-08 path). Feedback latency = arrival time − onset mapped to `performance.now()` through `getOutputTimestamp()`. | Gives the owner a way to measure their own hardware and feed real recordings back into tests. |
| D-30 | M2 curriculum order: meet guitar → first sound → pulse → frets on string 1 → string 2 → Em → Am + change → *Morning Steps* (original 8-bar piece) → listen & remember. | Follows spec §3.2 units 0–9; every lesson remains usable without a microphone. |
| D-31 | Chords are taught with diagrams, string-by-string isolated-pitch checks (one target per string, in order) and an unassessed strum-along. Chord completeness and chord changes are never scored. gu-score/1 stays monophonic. | Spec §5.3; a chord schema revision is deferred. |
| D-32 | Recall cue levels: full / reduced (no fret or finger numbers) / none (upcoming notes and the text tab hidden; the wait message doesn't reveal the note). The level is stored on each summary. | Spec "Recall" mode and "demonstration fades away". |
| D-33 | Retained = a cue-reduced/none microphone success (≥80 % pitch, ≥70 % coverage) on a later calendar day than an earlier microphone success on the same arrangement. Simulation or self-reports never qualify. | Spec §3.4. |
| D-34 | Adaptation offers (never automatic): two strong phrases → next tempo (or fixed mode from wait, or fewer cues at 100 %); two weak phrases → slower, then loop bar 1; low coverage → setup check. Microphone summaries only. | Spec §3.4 (+5 BPM mapped onto the 50/75/100 % steps). |
| D-35 | Tap-pulse compares `KeyboardEvent.timeStamp` / pointer time with each click's expected heard time (`getOutputTimestamp` mapping); labeled approximate, includes keyboard and output delay. | Spec unit 3 "tap-only/manual mode allowed". |

## M3–M5, independent reviews, redesign

| ID | Decision | Why / alternatives |
|---|---|---|
| D-36 | Three independent review agents (audio/assessment correctness, guitar-teacher content, UX/mobile) reviewed the M2 build read-only; every finding was triaged and applied or recorded (see ACCEPTANCE "Review findings"). | Owner asked for independent review of open items. |
| D-37 | Redesign: 5 tabs (Today, Learn, Practice, Tune, Settings) as a bottom tab bar on phones, an icon rail at 768 px, a labelled rail at 1280 px. Lessons, the player, songs, onboarding and camera are full-screen "focus" routes. Old URLs (`#/home`, `#/setup`, `#/data`, `#/diagnostics`, `#/tuner`) redirect. | UX review IA; one-handed phone use with the guitar on the lap. |
| D-38 | Design tokens per the UX review (warm paper surfaces, one blue for actions, status hues only for status; light/dark/high-contrast); system fonts only; original inline SVG icons; 48 px minimum targets; safe-area insets; `100dvh`. | Offline, no CDNs, wrappable later (Capacitor/TWA) without rework. |
| D-39 | "Advanced tools" switch (off by default) reveals the mic test lab, timing/devices, backup/restore, any-note tuner, look-ahead, simulated-player profile, dB readouts, score provenance and the camera experiment. | Owner: keep developer tools, but behind a button. |
| D-40 | Practice player: big "Up next" card (64/96 px fret numeral), highway ~44 dvh, one feedback line, fixed bottom transport with a 72 px Play, options in a bottom sheet / right drawer, Screen Wake Lock while playing; "How it went" leads with the one next step, then Right notes / On the beat / Heard clearly. | Readable from ~1 m; fixes the review's contradictory tally. |
| D-41 | Transport takes a pluggable `TimeMap`: constant tempo, or piecewise-linear alignment anchors (tick ↔ recording second). Backing recordings are scheduled per transport segment (start/stop with the segment), only at 100 % speed. | Spec TIME-02; no time-stretching (licensing/quality) in M3. |
| D-42 | Song workspace storage: IndexedDB v2 adds `songs`, `arrangements` (immutable versions keyed `id@version`) and `assets` (original audio Blob, SHA-256). Audio import limits: ≤ 25 MiB, ≤ 180 s, ≤ 2 channels, non-empty, decoded once. Rights question with three honest answers; "not sure" = private local practice only. | Spec §7.2, §10.2, §11.2. |
| D-43 | Alignment UX = tap along with the recording (least-squares beat fit, drift check on half-fits, residual/warnings) + ±20 ms nudges; anchors stored with the song. Linear only; drift and repeats are warned, not hidden. | Non-musician-friendly; piecewise multi-anchor editing is a later step. |
| D-44 | Score editor = string-grid (rows = strings, columns = eighths) for monophonic parts; placing a note trims/removes overlaps; undo/redo; every save is a new immutable version with a `manual_edit` log entry; validated before saving. | Spec §7.4 subset. |
| D-45 | Fingering planner: Viterbi over pitch-compatible positions with a transparent cost (hand shift, string crossing, higher fret, open-string bonus) per profile (beginner 0–3, open 0–5, full 0–12); impossible pitches return `no_playable_fingering`. | Spec §7.5. |
| D-46 | Easy versions (pulse / strong beats / easy melody): new arrangement with parent link, a transformation entry for every change and plain-language disclosures; only octave shifts and omissions change pitch content, so the key and a backing track stay compatible. | Spec §7.5 "never silently transpose over an unchanged backing". |
| D-47 | M4 transcription = the live analyzer run offline in a worker (no ML model): raw candidates (seconds) kept separately from quantized notes; tempo/downbeat estimate with half/double alternatives (or the tapped alignment); result is a `transcription_candidate` (`model_candidate`, unreviewed) that is never assessed until the learner marks it reviewed (`reviewed_part`, `user_reviewed`). Unclear sounds are shown as orange squares. A polyphonic provider (e.g. Basic Pitch) is *not* bundled. | Spec §7.3; candidate-review mode. Monophonic clean guitar only. |
| D-48 | M5 camera: opt-in, off by default, under Advanced. Mirror preview only (stored coordinates are un-mirrored); four-corner fretboard marks → homography → rough fret *region* of the index-fingertip landmark; evidence older than 250 ms is stale. MediaPipe Hand Landmarker 1.1.1 (Apache-2.0) + `hand_landmarker.task` (float16 v1, SHA-256 fbc2a300…) served from this origin, loaded only when the learner starts tracking, ~5 fps on the main thread. No grading, no contact/pressure/exact-fret claims, no audio fusion yet. | Spec §8: the 95 %-precision gate for corrective messages is not met (no data), so only a framing aid + narrow evidence. |
| D-49 | CSP adds `'wasm-unsafe-eval'` (WebAssembly compilation for the optional camera model) — still no `'unsafe-eval'`. | Needed by MediaPipe WASM; JS eval remains forbidden. |
| D-50 | Detector changes from the audio review: sustained-level check for any onset at a still-ringing pitch (no phantom notes from clicks/knocks), digital silence ⇒ `no_input_signal`/unavailable, YIN second pass at 0.2 (not for comb-separated estimates), separated pitches must differ from every recent pitch, onset refinement uses the 75th-percentile block, `onsetKind` exposed; matcher ignores click-tagged sounds and treats twelfth/double-octave as uncertain; wait mode replays notes played ≤ 0.35 s early and never records a flux-only wrong onset as the first attempt; loop-aware matching windows; judging waits for the analyser (lag guard); 48 kHz context; tuner listens down to 55 Hz and re-checks its lock; calibration stores output latency and is invalidated on a > 20 ms change; uncalibrated timing uses the browser's output-latency estimate. | Each was a confirmed or plausible failure mode on real hardware. |
| D-51 | Curriculum (teacher review): 14 lessons; *Morning Steps* comes before chords; new lessons: your hands, crossing strings 1–2, long notes and rests, chunks & memory (two-bar loops → from memory), all six open strings. Wrong-note feedback names strings and frets ("something may be pressing string 1", "fret 3 on string 2, one string away", "out of tune — visit Tune"). | Review notes; still unreviewed by a human teacher. |
| D-52 | Score format **gu-score/2** = superset of v1 (v1 files still valid): optional chord track (`chords`: frets per string, eighth-note strum pattern, never assessed), `sections`, `instrument.capo` 0–9 (frets count from the capo; `pitchMidi` sounding), per-note `techniques`, `arrangementLevel`, recordings ≤ 30 min, chord-only scores allowed. The melody/riff line stays monophonic; tunings stay standard; meter stays 4/4. Writers stamp the lowest version that fits (`withSchemaVersion`). | Needed for songs (chords, sections, capo) without loosening assessment. |
| D-53 | **Any song → Easy / Medium / Full** (`songArrange.ts`): Easy = easiest shapes (difficulty ≤ 2) with a capo when it saves ≥ 2 difficulty points, one strum per chord, strong-beat melody in frets 0–3; Medium = shapes ≤ 3 (capo allowed), four down-strums a bar, melody without very short off-beat notes in frets 0–5; Full = exact chords (lowest-cost voicing), `D-DU-UDU`, whole melody. Melody notes move only by octaves; chords keep their root (only notes are dropped: maj7→maj etc.). The learner picks *strum the chords* (no assessed targets) or *play the tune*. | User request: "easy, medium for hard learners, then full"; key never changes. |
| D-54 | **Song analysis** on device (classic DSP, no ML): tempo + DP beat tracking, downbeat, tuning, beat-synchronous chroma + HMM chords (maj/min/7/min7/maj7/5/N), key profile, predominant melody and bass by harmonic salience, novelty sections. Beats become piecewise alignment anchors (tick 0 = first downbeat). Results are candidates at every level until the learner presses "Sounds right" (then `user_reviewed`). | No server, no model download; honest candidate mode. |
| D-55 | Audio import limit raised to 15 min / 80 MB; playback copy decoded once to **mono 32 kHz** (~7.7 MB/min) and a 22.05 kHz copy rendered for analysis. | Whole songs on phones without exhausting memory. |
| D-56 | **Slow practice with the original recording**: WSOLA time-stretch (64 ms Hann frames, 50 % overlap, decimated cross-correlation search) made per speed in a worker and cached in memory for the session; the transport plays backing at a rate only once a stretched copy exists (`backingRates`). | Removes the "backing only at 100 %" limitation; pitch unchanged. |
| D-57 | **Importers**: MIDI (formats 0/1), ASCII tab (rhythm guessed from columns → never graded), chord sheets/ChordPro (lyrics dropped, capo chords converted to sounding chords), MusicXML (own tolerant XML reader), Guitar Pro 3–7 via `@coderline/alphatab` 1.8.4 (MPL-2.0) loaded lazily and cached by the service worker only on first use. Simultaneous fretted notes become chord shapes; single notes form the line; dead notes are never targets. | "Take any song, look at the notes and play". |
| D-58 | **Curriculum 1.0**: 70 lessons, 13 chapters, five tiers (bedroom → garage → open-mic → club → stadium), boss-fight review lessons, ranks (14), all original material; techniques are demo + self-check, bends assess only the plain target note, drop-D steps contain no assessed targets and are followed by "tune back". Still unreviewed by a human teacher. | User request: "from no one to bootleg Hendrix". |
| D-59 | **Coach voice** setting (plain / funny — default / metal): jokes are an extra line beside plain text, roast the gear never the learner, no slurs/sexual/nationality jokes; `plain` shows none. | User asked for humour; accessibility of instructions kept. |
| D-60 | **Visual identity "from the bedroom to the stadium"**: amp-orange actions, hot-pink/gold celebration, day + dark "stage" themes, Bebas Neue / Metal Mania (OFL, self-hosted) for display only, original inline-SVG art (pick logo, mascot "Picky", stage/venue scenes, rank shields, wood fretboard, chord boxes, strum arrows, 3+3 headstock), neon highway with per-string colours always paired with fret numbers. Design critique recorded in the run notes (HANDOFF). | User: "still simple — make it graphical, fun, mobile-native and PC friendly". |
| D-61 | **Tuner presets** (standard, drop D, half-step down, D standard, open G, open D, DADGAD) only change the tuner target; a callout says lessons expect standard tuning. | Variety for electric/metal/blues without breaking assessment. |
| D-62 | **Instrument profile** (acoustic / electric / nylon) only changes advice (e.g. clean tone while notes are checked; amp/volume safety). | The pitch checker cannot untangle distortion. |
